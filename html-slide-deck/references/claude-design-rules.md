# 事業用スライドテンプレート 制作ルール（2026-08-24 改訂）

正本は Claude Code 側の `html-slide-deck/references/design-system.md`。ここはその要約。食い違いがあれば正本が優先。

**最終成果物は、この `.dc.html` を pptx にしたあと作り手が手で仕上げたもの。** HTML 側で構造を作り込むほど pptx での手直しが重くなる。凝った作りより直しやすい作りを選ぶ。

## 新規スライド作成の標準手順
1. `readme.md`・`事業用スライドテンプレート.dc.html`（19 型）を先に読む
2. テンプレートを複製して新ファイル（`〇〇.dc.html`）を作り、中身を差し替える。ゼロから組まない
3. 渡された構成メモは鵜呑みにせず、(1) ストーリー (2) タイトル (3) リード文 (4) ボディの過不足 (5) 型とアイコンの選び方 を点検し、改善点を明示してから作る。新しい主張・数値は勝手に足さない
4. 構成は 表紙 → 振り返り（定例は必須）→ 本編（章が 3 つ以上なら章扉）→ まとめ → 付録
5. 仕上げに最低文字サイズ（本文 24px 以上・基本 26〜28px）と下の余白（30px ほど）を確認する
6. 発表者ノート（data-speaker-notes）は付けない

## 文章（最重要・2026-08-23 改訂）
- **リード文は結論＋判断理由・結果を 1〜3 行**。ボディの縮約にしない。「前回ご指摘をいただきましたので」型の応答文・予防線は書かない。【議論】は末尾に改行して聞きたいことを 1〜2 文
- **ボディは構成メモの項目を落とさない**。箇条書きは 1 項目＝短い文 1〜2 行、補足は子の箇条書き（2 階層まで）。体言の羅列にしない
- **「太字キーワード ── 短い説明」の 1 行圧縮はしない。「──」「―」「—」（長いダッシュ類）は全面禁止**（タイトル副題・kicker の日付・箇条書き見出し・ガントのトラック名とも）。見出しが要る箇条書きは「太字の見出し行＋次行から本文」か「見出し：本文」。トラック名は「実装／仕組みづくり」のようにスラッシュで並べる。kicker の区切りは「·」か空白
- **1 枚 1 テーマ**が第一。文字量の目安（図表と同居 7 本／約 350 字、文字だけ 10 本／約 600 字）は分割検討の目安で、テーマが割れるなら分けない。フォントを 24px 未満に落として詰め込まない
- 文字だけの枚（箇条書きだけ・論点を絞った議論）は可。主役の構造（表・フロー・進行表・カード列）は置けるときに置く
- タイトルは副題なしの名詞句 1 本。「〜を、〜に。」構文・動詞締めは使わない。表紙の大タイトルは定例名そのもの。**表紙にリード文（概要説明）は置かない**
- 口頭で補う説明・守りの理屈はデッキに入れない（構成メモの「設計判断」節に残す）。クライアントに pptx を渡す前提で、内情を残さない
- 数値はプレースホルダ。因果を断定しない。「PoC」表記

## 骨格と詳細（2026-08-24 改訂・最重要）
1 枚の骨格（流れ・対比・階層・並列の論点）はボックス・フロー・カード列で描き、**その中身は箇条書きで書く**。全部を箇条書きにするとコンサルの資料にならず、全部を箱に入れると読めない。

| 何を伝えるか | 描き方 |
|---|---|
| 大きな流れ・手順 | ステップカード列・横フロー |
| 並列の論点・柱 | 見出し帯カードを並べる |
| 対比・階層 | 2 分割・上下 2 段のカード |
| 各ブロックの中身 | 箇条書き（1 テキストボックス） |
| 列で読む必然があるもの（比較・進行表・突合・ガント） | 表 |

- **表は列で読む必然があるときだけ。** 列ごとに視線を走らせる用がなければカード＋箇条書きにする（pptx で行を足し引きしやすい）
- 罫線だけのカード（`border:1px solid #D8D6D0`・地は白）は塗りに数えない。並列を見せたいときはこちらを使う

## アイコン（2026-08-24 改訂）
- 線アイコン（`<use href="#ic-…">`・stroke 1.5・24 viewBox）は **見出し帯カードの見出しだけ** に置く（章扉の章名も可）
- **置かない**: 箇条書きの各行・番号付きリスト・表の行や行グループ名・ガントのトラック名・工程やステップのノード・表紙の「本日の流れ」・目次・文中・タイトル横・フッター
- 1 枚 0〜4 個。**アイコンが 1 個も無い枚があってよい**（表・進行表・ガント・箇条書きだけの枚は 0 個が既定）。5 個以上は多すぎる
- 同じサイズ（28〜40px）・同じ色（本文色 #2F3135）。強調 1 個だけ Klein Blue
- 概念とアイコンは 1:1 で固定。同じ概念に別のアイコンを使わない。絵文字・アイコンフォント不可

## デザインシステム
- 1920×1080・deck-stage 形式。白地 #FFFFFF（オフホワイト版 #F6F5F2）、本文 #2F3135、タイトル #111、注釈 #6F7175、罫線 #D8D6D0・弱罫線 #E6E4DE、淡ベージュ #F4F2EE、Klein Blue #002FA7（推奨・本命・キー数値・現在地・強調語句のみ。面積 5〜12%）、淡ブルー #EAF1FF、注意帯 #FFF4D7/#7A5200
- タイトル＝游明朝 64px、章扉 96px、リード文 36px（28〜38）、カード見出し 32px、本文 28px（26〜30・最低 24）、補助 24px（最低 22）、kicker・STEP のみ 18〜20 可、KPI 130px 明朝、コード最低 21px。補助ラベル・凡例・フッターは `data-role="caption"`、役割バッジ・評価チップは `data-role="badge"`、kicker・STEP は `data-role="kicker"` を要素に付ける（Claude Code 側の機械チェックが役割を判定するため）
- 本文スライドは `padding:56px 96px 104px`＋天地中央寄せ（flex column / justify-content:center）。footer・右上バッジは absolute。footer の `data-footer-title` / `data-page` を残す（Tweaks 連動）
- 脱ボックス: 塗りは区切る意味があるものだけ（対比・見出し帯・記入欄・表）、1 枚 2〜3 個まで。列挙は箇条書き＋弱罫線。カードは見出し帯だけ淡色地。グラデ・影・角丸・ブロブなし。濃ベタ＋白文字は最小限
- 画像は生成しない。破線枠 `2px dashed #B7B7B7`＋地 #FAFAF8＋「何を写すか」の指示文

## PPTX 手直し前提の作り
- 箇条書き・複数行テキストは 1 つの要素（1 テキストボックス）にまとめる。`・項目<br>・項目` を 1 つの div に。例外は行ごとに背景・罫線が要る表・ステップカード
- 帯・カード・バッジは 1 つの塗り矩形（背景色つき div）
- **ガントは全体を 1 つの grid で組む**。`grid-template-columns:<ラベル幅> repeat(N,1fr)` を 1 箇所だけ宣言し、月ヘッダ・週ヘッダ・トラック見出し（`grid-column:1/-1`）・ラベル・帯（`grid-column:a/b`）をすべてその直接の子に置く。行ごとの flex ＋入れ子 grid にしない（月・週・帯の縦線がずれる）。grid に `gap` を入れず、帯の余白は帯自身の `margin:0 3px`。帯の無い週もプレースホルダの div で埋める。週の縦線はオーバーレイ 1 枚（同じ列の値）。ラベルは `white-space:nowrap` で 1 行に収める。実施済み＝緑・今週＝先頭週に印。1 枚 4 トラック 12 行程度が上限

## 構成・トーン
- 定例は「会話する場」として設計。役割バッジ（報告／確認／議論／参考／再掲）を全ページに。【議論】は 1 論点 1 枚、方針＝たたきを直接提示（選択肢比較は依頼時のみ）。議論の手前に【再掲】の全体像 1 枚
- **振り返りは 1 枚**。左に前回の振り返り（決定事項・その場で出たアクション）、右に今週実施したこと、どちらも箇条書き。**「使った時間」の欄は置かない**（画面共有で見せるものは項目末尾に括弧書き）
- **前回資料から流用できる枚（目的・コンセプト・全体像）は作り直さない**。破線枠（`2px dashed #B7B7B7`・地 #FAFAF8）に元ファイル名・ページ番号・そのページの見出し・差し替え時に更新する箇所を書き、pptx 化のあと作り手がそのページを貼り替える。タイトル・kicker・役割バッジは通常どおり入れる
- まとめは「本日の内容＋次回までの動き（自分側のみ）」。「お伺いしたいこと」はまとめにだけ、その場で答えが返る問いだけ。持ち帰り論点は議論した回だけ
- 相手側の宿題・固有の約束・未確定の担当者名や期日は書かない。用語は現場で通じる言葉に
- 「皆様」「お気軽に」の包摂的トーン。メンバー本人が読んで評価的に響かない書き方。議事録・内部パス・内部運用メモを本文に書かない
- 付録は「迷ったとき引く 1 枚」に絞る。前提・準備は使う本編の直前に置く

## 型（19＋1）
表紙／目次／自己紹介／章扉／現状と目指す姿／提供価値 3 軸／比較表／4 ステップ／推進体制／スケジュール（月帯）／ガント（タスク×週）／KPI／ロードマップ／**振り返り**（左右 2 カラムの箇条書き）／確認事項／議論／まとめ／付録 早見表／お問い合わせ＋**進行表**（案件ごとに「仕組みの整備」「メンバーの利用」の 2 段・横方向にステップ。定例で更新し続ける）＋**流用枠**（前回資料のページを差し替える破線枠）
