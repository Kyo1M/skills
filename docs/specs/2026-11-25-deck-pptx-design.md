# pptx を組む共通 skill（deck-pptx）設計書

- 日付: 2026-11-25
- ステータス: レビュー待ち（brainstorming で方式・分担・部品・確かめ方を論点ごとに合意し、AI レビュー 2 件の指摘を反映した。試用と比較検証を経て正式版にする）
- 対象: 2 つのクライアント案件のリポジトリに分かれている pptx の組み立て（構成 md → pptx）を、どのリポジトリでも使える skill `deck-pptx` として `~/Developer/Skills` に作る。事業用スライドテンプレート（ロゴあり・ロゴなし）を同梱し、別の Mac の Claude Code でも「構成 md → 批評 → pptx → インフォグラフィック案」を回せるようにする
- 対象外: 配布先の会社向けの別テンプレートの作成、案件リポジトリにある既存の組み立てスクリプトの置き換え・削除、案件リポジトリに配っている deck-infographic の写しの同期、PowerPoint で編集できるグラフの新規作成、Windows の書体への対応、claude.ai への配置

## 1. 決めたこと

| 論点 | 決定 | 理由 |
|---|---|---|
| skill の分け方 | 1 つにまとめず、`deck-pptx` を 1 つ足す。入口の `deck-outline` に 4 工程の流れを書く | 批評は作成とは別の目で行う。インフォグラフィック案は完成した pptx に後からかける。まとめると SKILL.md が長くなり、起動する依頼があいまいになる |
| 組み立ての方式 | 共通の部品＋資料ごとの短い組み立てスクリプト（`build.py`）。Claude が資料ごとに部品を呼ぶスクリプトを書く | 既存のスクリプトも、ページごとの組み方を資料ごとに直書きしていた。どの資料にもそのまま使える変換器は実際には無く、図解・独自の図のページは資料ごとの記述が要る |
| 土台の選び方 | 2 通りを同じ部品で扱う。新しい資料はテンプレートから、定例のように前回の資料がある資料は前回の最終版から始める | 今の定例資料は、前回の最終版のページを複製・並べ替えて骨格にし、再掲のページを前の資料から写している |
| 定例資料の土台 | 前回の最終版をそのまま土台にする。テンプレートへは移さない | 今の定例資料は見た目こそ同じデザイン（ロゴなし）だが、HTML から書き出した系統のファイルで、テンプレートの pptx とは大きさ・レイアウト・枠の作りが異なる。これまでの回と見た目を変えず、比較で分かることを作り方の違いだけにする |
| 土台ごとの違いの吸収 | 座標と文字の大きさを 1920×1080 の px で書き、土台のスライドの大きさに換算する。枠（題・リード文・フッター）の見分け方などの違いは「土台の設定」に持つ（4.4） | 今の定例資料は 1440×810pt で、題とリード文は名前付きの図形。テンプレートは 960×540pt で、プレースホルダー。同じ 16:9 で、文字の大きさの比もスライドの幅の比と同じ |
| 完全自動の変換器 | 作らない | 箇条書き・表・図・2 列の単純なページしか組めず、テンプレートの図解の型を表せない |
| テンプレート | ロゴあり・ロゴなしの 2 版を、掃除してから `deck-pptx/assets/templates/` に置き、ここを正本にする（7 章）。事業用のリポジトリ側は README から Skills を指す | 写すと正本が 2 つになる。今のファイルはノートに他社のテンプレート名があり、ロゴなし版にロゴの画像が残っている |
| ロゴの扱い | ロゴあり版も公開する。LICENSE でロゴ・社名を対象外にし、skill は資料ごとにどちらの版かを確かめる（迷ったときの既定はロゴなし） | 社名を知ってもらうきっかけになる。第三者がロゴを消し忘れた資料を作る懸念は、ライセンスの記載と既定で抑える |
| 案件のコードの扱い | 写さずに一般化して書き直す。案件名・拠点名などの固有名・人名・顧客の社名を含めない | Skills は公開リポジトリ |
| 公開（push）の条件 | テンプレートの掃除（7 章）と公開の前の確認（8.2）が済んでから、Draft PR として push する。済むまではローカルのコミットだけにする | push した時点で、ブランチの全コミットとテンプレート・ロゴが公開される |
| 禁止語の一覧と検索の仕組み | 今は作らない。公開の前の確認は手順として行う（8.2） | 案件の資料は案件リポジトリの外に出さない決まり（9 章）と、初回の確認で足りると判断した。漏れが起きたとき・人が増えたときに作る |
| テンプレートの構造の参考元 | ノートを外したうえで MIT で公開する | 依頼者が確認済み |
| 編集できるグラフ | 新しいグラフは PNG で貼る | 依頼者が確認済み |
| インフォグラフィック案の文字 | 図の中の文字を pptx のテキストボックスにし、PowerPoint で直せるようにする（10 章） | pptx の上で修正・レビューすることが多い |
| 依存の入れ方 | 各スクリプトと資料ごとの `build.py` の先頭に依存を書き、`uv run` で動かす | 別の Mac で仮想環境を作る手順が要らない |
| 正式版にする条件 | 次回の定例資料を、既存のやり方と `deck-pptx` の 2 通りで作って比較し、同等以上と確かめてからマージする（9 章） | 今の資料の品質を下げない |
| 設計書の置き場 | `docs/specs/` | このリポジトリの既存の設計書に合わせる |

## 2. 全体の流れ

```
deck-outline ─→ deck-critique ─→ deck-pptx ─→ deck-infographic
 構成 md         構成 md の批評     pptx          図の案を足した版
```

| skill | 役割 | 今回の変更 |
|---|---|---|
| deck-outline | 構成 md | Phase 6 の「pptx を直接作る」の確かめ方 4 行を `deck-pptx` への参照に置き換える。4 工程の流れの表を置く |
| deck-critique | 批評 | なし |
| deck-pptx（新規） | 構成 md → pptx、既存 pptx の版上げ（文言・表・図の差し替え） | 新規 |
| deck-infographic | 完成した pptx に図の案を足す | pptx を画像にする手順（手順 4 の 3）、文言の書き出し、パッケージの確認を `deck-pptx` のスクリプトへの参照にする。図を描くスクリプトを `uv run` で動く形にする。図の中の文字を pptx のテキストボックスにする（10 章） |
| html-slide-deck | HTML の経路 | なし。面の使い方の正本（`references/design-system.md`）は今のまま、`deck-pptx` から参照する |

deck-infographic は今、claude.ai から同期された pptx skill の `slide_text.py`・`validate.py` を呼んでいる。別の Mac にはこの同期が無いことがあるので、同じ役割のスクリプトを `deck-pptx/scripts/` に持つ。

## 3. deck-pptx のフォルダ

```
deck-pptx/
├── SKILL.md
├── assets/templates/
│   ├── continova-business-template.pptx / .potx / -preview.pdf   ロゴあり
│   └── unbranded-business-template.pptx / .potx / -preview.pdf   ロゴなし
├── scripts/
│   ├── outline.py        構成 md を読む（--check で読めない行を出して止める）
│   ├── parts.py          部品（文言・図形・表・図）
│   ├── template.py       土台の操作と土台の設定（--inspect）
│   ├── pptx_to_png.sh    pptx → PDF → 全ページの PNG（LibreOffice・poppler）
│   ├── slide_text.py     pptx の全ページの文言を書き出す
│   ├── check_text.py     構成 md と pptx の文言の照合
│   ├── check_package.py  pptx のパッケージの確認（PowerPoint が修復を求めないこと）
│   └── selftest.sh       skill そのものの確認
└── references/
    ├── type-map.md       構成 md の型 → テンプレートのレイアウト・サンプルページの対応表
    ├── example-outline.md 架空のテーマの構成 md
    ├── example-build.py  その組み立て例（新しい資料はこれを写して始める）
    ├── example-revise.py 版上げの例（前回の資料を土台にする・ページを写す・文言を差し替える）
    └── template-guide.md テンプレートの使い方とロゴの差し替え方
```

`pptx_to_png.sh` の名前は、deck-infographic の `render.sh`（図 → PNG）と分ける。selftest の出力は一時フォルダに出し、リポジトリの中に pptx・PNG を作らない。

テンプレートは 16:9（960×540pt）、スライドマスター 1 つ、レイアウト 20 種（`01｜表紙`〜`20｜白紙`）、編集できるサンプル 32 枚。書体はヒラギノ明朝 ProN（見出し）とヒラギノ角ゴシック（本文）で、ファイルに埋め込んでいない。

## 4. 部品

資料ごとの `build.py` は、次の 3 つのモジュールを読み込んで使う。`build.py` の先頭に依存（python-pptx・lxml・Pillow）を書き、skill の場所を環境変数 `DECK_PPTX`（既定は `~/.claude/skills/deck-pptx`）から読み込み先に足す。絶対パスを直書きしない。

### 4.1 outline.py

読む文法は次のとおり。`deck-outline/references/output-template.md` の形式と、今の 2 つの案件の構成 md の書き方の両方を読めるようにする。

- ページの見出しは `###` か `####` ＋ ID ＋題。ID は英字 1 字＋番号＋枝番（`S1`・`A2`・`S7b`・`R1`）
- 欄は `- **タイトル**: …` の形。全角コロン、欄名の後ろの括弧書き（`**役割（制作用）**`）も読む。題の欄が無ければ見出しの題を使う
- リード文は 1 行の値と、子の箇条書き（1 行 1 項目）の両方を読む
- ボディの箇条書きは階層を保って読む（段数を決め打ちしない）。複数項目のセルの表は「行の見出し → 列名 → 項目」の 3 階層で書かれる
- md の表、図のパス、図版指示の型の名前を取り出す
- 載せる欄（題・kicker・リード文・ボディ）と載せない欄（役割・図版指示・スクショの指示・補足）を分けて持つ
- `--check` は、読めなかった行・知らない欄・ID の重複を行番号付きで出し、1 つでもあれば失敗で止める。警告だけで続行して文言を落とさない

### 4.2 parts.py

| 分類 | 部品 |
|---|---|
| 文言 | 書式を保った段落の差し替え、`**太字**`・`{強:…}`（青の太字）・`{悪:…}`（赤の太字）・`{良:…}`（緑の太字）・`{灰:…}` の強調、「（TODO: …）」を赤にする処理、リンク付きの文字、リード文（行数からボディの上端を決める）、青い角の箇条書き（折り返し行を本文の先頭にそろえる）、全角・半角の幅から行数と高さを見積もる関数、文字の大きさの候補から枠に収まるものを選ぶ関数 |
| 図形 | テキストボックス、線・矢印、小見出し（下線付き）、見出し帯カードの列（番号付きも）、主体付きのステップノード列、マトリクス（列の見出しはシェブロンか帯。成果の列への矢印）、シェブロンの工程、工程と説明を列でそろえたフロー、月の帯、2 軸の 4 象限、見えたことの枠（淡い青の地＋左の青い線）、お伺いしたいことの枠、注意の帯、ページの下の注 |
| 表 | 土台の書式の表（見出しは補助面の色・灰色の太字、本文は白地、細い罫線）、同じ値が続く左端のセルの結合、セルの強調、列幅の自動調整、行数から行の高さを見積もる関数、セルの中の「・」の箇条書き、ガント（タスク×週） |
| 図 | 比率を保って枠に収める配置、左に図・右に枠のページ、幅いっぱいの図、既存の図の差し替え、撮影前の図・スクショの枠（何を写すかを書いた灰色の枠。図のファイルが無いときに置く） |
| 版上げ | 図形を ID か名前で取る・動かす・外す・複製する、既存の表の枠を保った作り直し |

色はアクセント `#002FA7`、本文 `#111111`、補助の文字 `#6F7175`、補助面 `#F4F2EE`、罫線 `#D8D6D0`、淡い青 `#EAF1FF`、悪くなった値の赤 `#C0392B`。2 つ目の区分の色とよくなった値の緑は、実装のときに今の資料の値を確かめて定数にする。

### 4.3 template.py

- 土台を開く（テンプレートの `.pptx`・`.potx`、前回の資料の pptx）
- サンプルページをすべて外す
- レイアウト名の先頭（`05` など）でページを足す。使わないプレースホルダーを外す
- ページを複製する・並べ替える・外す（前回の資料から骨格を作る）
- 枠（題・リード文・罫線・フッター）だけを残して本文の図形を外す
- 別の pptx のページを写す（再掲）。題とリード文は差し替えられる
- ページ番号は PPTX の標準のスライド番号フィールドにする（`html-slide-deck/references/automatic-slide-numbers.md`）
- 保存のときの後始末をする

ページを複製する・写すときの扱いを決めておく。

| もの | 扱い |
|---|---|
| 画像 | 写す |
| 外部へのリンク | 写す |
| 編集できるグラフ（既存のもの） | 同じ資料の中の複製では保つ。別の pptx から写すときは未対応として止め、画像にして貼るかを依頼者に聞く |
| 資料の中の別ページへのリンク | 外して、外したことを出す |
| ノート・コメント | 持ち込まない（deck-infographic と同じ決まり）。依頼者のコメントは、外す前に読んで一覧に出す |
| 上のどれでもない関係 | 黙って落とさず、止めて何があったかを出す |
| スライドの大きさが異なる pptx からの写し | 図形の位置と大きさ・文字の大きさを比で換算する。レイアウトは土台の白紙に当てる |

保存のときの後始末:

- `docProps` の資料の題・ページの題の一覧・枚数を、出力の中身に合わせて書き直す（前回の資料のページの題を残さない）
- 使っていない画像の関係と、外したページへのリンクを外す（レイアウトは PowerPoint でページを足すのに使うので残す）
- `check_package.py` を通す（パーツの重複、関係の切れ、`[Content_Types].xml` の不足が無いこと）

### 4.4 土台の設定

土台ごとに異なる値を 1 か所に持ち、部品はこの設定を通して描く。

| 項目 | テンプレート | 前回の資料 |
|---|---|---|
| スライドの大きさ | 960×540pt | 資料から読む（今の定例資料は 1440×810pt） |
| 枠の見分け方 | プレースホルダーの番号（題 0、リード文 1、ページ番号 99） | 図形の名前（題・リード文・フッター・ページ番号）か、上端の高さ |
| ボディの範囲 | 定数 | リード文の下からフッターの線の上まで。資料から測る |
| 文字の大きさ（題・リード文・本文・表・注） | 定数 | 資料の同じ役割の図形から読む |
| 色・書体 | 定数 | 資料のテーマと図形から読む |

- テンプレート用の設定は `template.py` に同梱する
- 前回の資料用の設定は、`template.py --inspect <pptx>` が候補を出し（図形の名前・位置・文字の大きさ・色の一覧）、資料の `build.py` の先頭に書く
- 部品の座標と文字の大きさは 1920×1080 の px で書く（`design-system.md`・deck-infographic と同じ）。設定のスライドの大きさで換算する

### 4.5 入れないもの

- 案件に固有の部品（特定の区分の列にそろえたブロック、実データの表、特定の指標のグラフ）
- ページ番号ごとに組み方を直書きした対応表。組み方は資料ごとの `build.py` に書く
- PowerPoint で編集できるグラフの新規作成。分析の図は PNG で貼り、要る資料が出たときに足す

## 5. 型の対応表（type-map.md）

構成 md の図版指示は、`html-slide-deck/references/slide-patterns.md` の型の名前（01 表紙〜20 進行表、箇条書き型など）で書かれている。型ごとに、テンプレートのどれで受けるかを 1 行ずつ決める。受け方は 3 通り。

| 受け方 | 理由 |
|---|---|
| サンプルページを複製して文言を差し替える | 図形の組み方が込み入っていて、位置をコードで書き直すより作例を写すほうが崩れない |
| レイアウトに部品を置く | 項目数で形が変わる |
| 前の資料のページを写す | 再掲・流用のページ |

初版の割り当ては次のとおり。部品は `slide-patterns.md` の各型の決まりに合わせる。実装のときにサンプルページの実物と照らして確かめ、`type-map.md` には「項目数の上限」と「項目数が作例と合わないときの組み方」の列を足す。

|---|---|---|---|
| 01 表紙 | レイアウト | `01｜表紙` | プレースホルダー |
| 02 目次 | サンプル | 「目次」 | 段落の差し替え |
| 03 自己紹介 | サンプル | 「自己紹介」 | 段落の差し替え |

## 6. SKILL.md の手順

新しく作るときと版を上げるときで、文言の正本が異なる。

| 場面 | 文言の正本 | 照合の相手 |
|---|---|---|
| 新しく作る（依頼者が PowerPoint で手直しする前） | 構成 md | 構成 md の載せる欄のすべて |
| 版を上げる（手直しした pptx を受け取った後） | pptx | 差し替える箇所の一覧だけ。それ以外のページは元の pptx と変わっていないこと |

### 6.1 新しく作る

1. **入力を確かめる。** 構成 md（必須。`outline.py --check` を通す）と図の PNG
2. **土台を決める。** 前回の資料がある定例などは前回の最終版から始め、新しい資料はテンプレートから始める。テンプレートはロゴあり・ロゴなしのどちらかを依頼者に聞く。リポジトリの規約に指定があればそれに従う。迷ったときはロゴなし。前回の資料は制作記録・更新日時・ページ数で最新を確かめ、PowerPoint で開いているファイル（`~$` のファイルがある）は読むだけにする
3. **型を決める。** 構成 md の図版指示を `type-map.md` に当て、ページごとの受け方を表にして依頼者に見せる
4. **代表の 3〜4 枚を先に組む。** 題・リード文・フッターの位置、余白、強調色の量を画像で確かめてから全ページに広げる
5. **全ページを組む。** `example-build.py` を作業フォルダに写して `build.py` を書く。文言は構成 md から読み、スクリプトに書き写さない。箇条書きは 1 つのテキストボックス、帯・カードは 1 つの塗り矩形にし、ページ全体を 1 枚の画像で貼らない
6. **確かめる。** `pptx_to_png.sh` で全ページを画像にし、`check_text.py` と `check_package.py` を通す。画像で見る点は、型どおりか、はみ出し・重なり、1〜2 文字だけの折り返し・語の途中の折り返し、行頭の空白、同じ役割のページの位置のそろい。3 回で収まらなければ残る差を添えて依頼者に聞く
7. **渡す。** 残る差を並べ、PowerPoint か Keynote で見てもらう（LibreOffice の描画は PowerPoint と完全には一致しない）。置き場と名前はリポジトリの規約に従い、無ければ構成 md と同じフォルダに `<日付>_<題>_v1.pptx`

### 6.2 版を上げる

1. 依頼者が手直しした最新の pptx を元にする。構成 md から作り直して手直しを消さない
2. 差し替える箇所（ページ・図形・新しい文言・表・図）を一覧にして依頼者に確かめる
3. `example-revise.py` を写して、一覧の箇所だけを差し替える `build.py` を書く（版上げでは、差し替える文言をスクリプトか一覧のファイルに書いてよい）
4. `check_text.py --against <元の pptx> --changes <一覧>` で、一覧の箇所が入ったこと・それ以外のページの文言が元と変わっていないことを確かめる。画像と `check_package.py` は 6.1 と同じ
5. 最終版を保存したら、構成 md をその版に合わせる（deck-outline の決まり）

出力の置き場・外に出してよい範囲（実名の入る pptx をコミットしないなど）は、対象リポジトリの AGENTS.md / CLAUDE.md から読む。

案件リポジトリの規約に書かれている、pptx を組むときの一般的な決まり（折り返しと行頭の点検、表の中の箇条書きを編集できる段落にする、左端の列のセルの結合など）は、書き方原則と照合し、共通側に無いものを 6.1 の手順 6 の見る点に足す。案件の事実・好みは取り込まない。

### 6.3 check_text.py の照合

- 構成 md の載せる欄（題・kicker・リード文・ボディの箇条書き・表のセル）を、ページごとに pptx の同じページの文言と照らす
- 照らす前に、強調の記法（`**`・`{強:…}` など）と箇条書きの記号を外す。全角半角・数字・単位はそのまま比べる
- 出すもの: 欠けた文言、別のページに入った文言、構成 md に無い文言（複製元の文言の残り）、同じページの中の重複
- 再掲のページ（構成 md では空ページ）は照合から外し、写したページの題だけを出す
- 「（TODO: …）」は残っている数を出す（失敗にはしない）
- 画像の中の文字は対象外。図の差し替えは目で確かめる

## 10. インフォグラフィック案の文字の編集

今の deck-infographic は、図の中の文字も PNG に焼き込んでいる。図の見た目はそのままに、文字を PowerPoint で直せる形にする。

| もの | 今 | 変更後 |
|---|---|---|
| 題・リード文・フッター | pptx の文字 | 変えない |
| 図の中の文字（見出し・ラベル・説明） | PNG の中 | pptx のテキストボックス |
| 箱・円・矢印・アイコン・円弧 | PNG の中 | PNG の中（変えない） |

作り方:

- `figlib.py` の `text`・`lines` が、描いた文字の位置・大きさ・色・太さ・そろえ（左・中央・右）を控える。図の文字はこの 2 つの関数からしか出ていない
- `write` が、文字を抜いた図（SVG → PNG）と、文字の一覧（JSON）を出す。確かめ用に、文字入りの PNG も今までどおり出す
- `build_deck.py` が図の PNG を貼ったうえで、一覧の文字を同じ位置にテキストボックスで置く。図の座標は pptx のページと同じ 1920×1080 なので、`deck-pptx` の部品（px を土台の大きさに換算する）で置ける
- テキストボックスは折り返しなし・余白なしにし、そろえは控えた値のとおりにする（中央そろえの文字は、書体で幅が変わっても中心がずれない）
- 図の PNG と文字を 1 つのグループにまとめる（図を動かすと文字も一緒に動き、グループの中の文字はそのまま直せる）
- 回転した文字など、テキストボックスで同じ見た目にならないものは PNG に残し、残したことを `build-report.json` に書く
- 今までの文字入りの PNG だけのページも `--text image` で作れるようにする（既定は pptx の文字）

確かめ方: 文字入りの PNG（今までの見た目）と、新しいページを画像にしたものを並べ、文字の位置・大きさ・折り返しのずれを見る。selftest の図 1 枚でも同じ比較をする。

箱・矢印まで pptx の図形にすることは、今回は行わない。文字の修正が PowerPoint でできれば、レビューの大半は足りると見ている。図形の配置まで PowerPoint で直したい場面が続くようなら、次に検討する。

この変更は 12/4 の比較（9 章）の前提にしない。deck-pptx の本体のあとに実装する。
