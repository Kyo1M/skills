# deck-infographic — 既存資料のインフォグラフィック案

文章だけでは掴みにくい全体像・役割分担・情報の流れを、図を見れば分かるページにする。**既存のページは変えず**、図の案を別ページとして足し、最終的な取捨選択は依頼者に任せる。

## 入力

1. **最新版の pptx**（必須）。版の番号だけで決めず、制作記録 md・ファイルの更新日時で最新を確かめ、依頼者に一言で確かめる。
2. **構成 md・制作記録**（あれば）。各ページの実文言と、確定していない事項（TODO・確認待ち）を知るため。
3. **過去の図解案**（あれば）。内容とデザインの参考にするが、清書はしない。

## 出力（既定。リポジトリの規約に置き場があればそれに従う）

| もの | 置き場と名前 |
|---|---|
| 図の PNG | 作業フォルダの `inputs/<版>/NN-<内容>.png`（3840×2160） |
| 図を描くスクリプト・SVG・HTML | 作業フォルダの `source/<版>/` |
| 新しい版の pptx | 元の名前の版だけ上げる（`…_v7.pptx`）。図だけを確かめる 1 枚もの（`…_v7_インフォグラフィック案.pptx`）を先に作ってもよい |
| 候補一覧と制作記録 | 構成 md の置き場に `<日付>_<スラグ>-<版>.md`（候補一覧）と `-production.md`（制作記録） |

元の pptx は上書きしない。PowerPoint で開いている（同じフォルダに `~$<名前>.pptx` がある）ファイルは読むだけにし、コピーから作る。

## 手順

### 1. ページの棚卸しと候補一覧（描く前に 1 回確認）

1. `python <pptx skill>/scripts/slide_text.py <最新版>.pptx` で全ページの文言を出し、画像にして全体を見る。
2. ページごとに図にする価値を判定し、候補一覧 md を作る。列は「元のページ｜タイトル｜図の型｜図で伝える関係（1 行）｜図に入れる実文言」。
   - **対象**：全体像、役割分担（人と AI、組織と現場）、情報の流れ、工程、比較、循環、前提と結果の関係を文章で説明しているページ。
   - **対象外**：表紙・目次・章扉、スクリーンショットや実画面が主役のページ、すでに図が主役のページ、手順の細部・注意事項・TODO が主役のページ、文がごく短いページ。対象外にした理由も一覧に 1 語で残す。
   - 同じ関係を描く候補が複数ページにあるときは 1 つに畳み、どこに置くかを書く（原則 3）。
3. 候補一覧を依頼者に見せ、対象ページと図の型を 1 回だけ確かめてから描く。依頼者が「全部任せる」と言っていれば確認は省き、一覧は記録として残す。

### 2. 図を 1 枚ずつ描く

`references/example-cycle.py` を写して始める（アイコン・文字・円弧・矢印の部品が入っている）。

1. 図の型を内容から選ぶ（`references/figure-types.md`）。元の配置をなぞらず、関係が一目で分かる配置・視線の流れ（左上 → 右下、中心 → 周り）にする。
2. 文言は元ページか依頼文の実文言をそのまま使い、図の側で新しい主張・工程・実績・数値を足さない。足してよいのは「図の見方」「この循環を支えるもの」のような読み方のラベルだけで、足したものは記録に書く。
3. `scripts/render.sh <図のスクリプト.py> <出力.png>` で HTML・SVG・PNG を書き出す。
4. 確かめる（毎回）：
   - PNG が 3840×2160 であること（Chrome が高さを切ることがある）。
   - 図に入れるべき文言を SVG に grep し、全部あること。
   - Read の表示は縮小されるので、文字が密な所を 3〜4 か所、原寸で切り出して見る（文字と矢印の重なり、切れた字、明朝とゴシックが当たっているか）。
5. 最初の 1 枚は、すぐ依頼者に見せて方向性を確かめてから残りを描く。

### 3. 新しい版の pptx

1. 最新版をコピーし、図の案を元のページの直後に足す。案のページは PNG をページ全面に貼り、右下に小さく「元p.N 差し替え候補」を入れる（ページの通し番号ではなく元のページ番号）。
2. ページの複製・挿入は pptx skill の `scripts/add_slide.py` か、python-pptx で足してから `<p:sldIdLst>` を並べ替える。元のページの XML・画像はバイト単位で元と一致することを確かめる。
3. `python <pptx skill>/scripts/office/validate.py <新版>.pptx --original <最新版>.pptx` を通し、画像にして全ページを見る。

### 4. 記録と仕上げ

- 制作記録に、出力のパス、作り方（「SVG を Python で描き、Chrome headless で PNG に書き出した」）、足した読み方のラベル、対象外にしたページと理由、確かめたこと・確かめていないこと（PowerPoint での実表示、依頼者の採否）を書く。
- 全部描き終えたら、仕上げに 1 回だけ、作成とは別の目でレビューする（グローバルの CLAUDE.md の手順。材料は候補一覧 md・PNG・元のページの画像・依頼文。見るのは、元のページとの食い違い、新しい主張の混入、矢印の意味の取り違え、AI が最終判断して見える図）。

## デザインの既定（依頼に指定があればそちらに従う）

- 横長 16:9、キャンバス 1920×1080 を 2 倍で書き出す。白地。
- 色は濃い青（`#0035B4`）・薄い青（`#EEF3FC`、線は `#D3DDF3`）・濃いグレー（文字 `#2F3437`、補足 `#5F666D`、別の意味の線 `#6B737B`）。
- タイトルはヒラギノ明朝、説明とラベルはヒラギノ角ゴ（W3 と W6）。タイトル 54px、リード 28px、ラベル 26px、説明 21〜24px、凡例 17px を目安にする。
- 線画のアイコン（線の太さ 2px 前後、角丸）と、意味のある図形・矢印を使う。写真・立体・派手な装飾・ロボットのキャラクターは使わない。
- 文字を四角い箱に入れて並べるだけの構成にしない。箱を使うのは土台・帯など図の中で役割があるときだけ。
- 余白を取り、文字と矢印を重ねない。説明文は短くし、図を主役にする。
- ロゴ・ページ番号・Confidential・制作上の注記は図に入れない（pptx の候補ページのフッターは別）。
- 図の中も和文と英数字の間に半角スペースを入れない（原則 73）。

## 内容の決まり

- **矢印の意味を分ける**：作業の順序（実線）、情報の参照・更新（点線）、改善の戻し先（灰色の破線）のように線の種類で分け、2 種類以上使うときは凡例「図の見方」を置く。
- **人と AI を見分けられるようにする**：位置（左右・上下）と塗り（人は塗り、AI は白抜き）で分け、凡例に書く。
- **AI が最終判断する図にしない**。採否・確定は人の側に置く。AI による記録・更新にも、人が確かめる印を付ける。
- 根拠のない実績・数値・新しい工程を足さない。品質の向上を「ミスが無くなる」と書かない。
- 未確定の事項（TODO・確認待ち・提供前の機能）は、元のページの書き方より強く断定しない（原則 35・53）。

## 落とし穴

- SVG の文字は折り返さない。改行は手で入れ、1 行の幅は「文字数 × 文字サイズ」で見積もってから置く。
- アイコンを `scale()` で拡大するときは `stroke-width` を倍率で割る（`vector-effect` は `<g>` から継がない）。
- `marker` の矢じりは線の色ごとに定義する。
- Chrome は `--headless=new --force-device-scale-factor=2 --window-size=1920,1080 --screenshot` で書き出す。フォントは OS のものが当たるので、Mac 以外で書き出すときはフォントを確かめる。
- 図を pptx にしたあとは編集できない。文言を直すときはスクリプトを直して書き出し直す。
