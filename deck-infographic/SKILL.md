# deck-infographic — 既存資料のインフォグラフィック案

文章だけでは掴みにくい全体像・役割分担・情報の流れを、図を見れば分かるページにする。**既存のページは変えず**、図の案を別ページとして足し、最終的な取捨選択は依頼者に任せる。

案のページは、タイトル・リード・罫線・フッターをテンプレートと同じ pptx の文字で残し、**本文の範囲だけ**を図の画像にする。タイトルやリードは後から PowerPoint で直せ、ページを差し替えても資料の見た目がそろう。

## 入力

1. **最新版の pptx**（必須）。版の番号だけで決めず、制作記録 md・ファイルの更新日時・実際のページ数で最新を確かめ、依頼者に一言で確かめる（記録のページ数と実物が食い違うことがある）。
2. **構成 md・制作記録**（あれば）。各ページの実文言と、確定していない事項（TODO・確認待ち）を知るため。
3. **過去の図解案**（あれば）。内容とデザインの参考にするが、清書はしない。

## 出力（既定。リポジトリの規約に置き場があればそれに従う）

| もの | 置き場と名前 |
|---|---|
| 図の PNG | 作業フォルダの `inputs/<版>/NN-<内容>.png`（本文の範囲の 2 倍。既定のテンプレートなら幅 3456） |
| 図を描くスクリプト・SVG・HTML・JSON | 作業フォルダの `source/<版>/figNN_<内容>.py` ほか。`figlib.py` も同じフォルダに写す |
| 新しい版の pptx | 元の名前の版だけ上げる（`…_v7.pptx`） |
| 候補一覧と制作記録 | 構成 md の置き場に `<日付>_<スラグ>-<版>.md`（候補一覧）と `-production.md`（制作記録） |

元の pptx は上書きしない。PowerPoint で開いている（同じフォルダに `~$<名前>.pptx` がある）ファイルは読むだけにし、コピーから作る。出力の pptx を作り直すときは、PowerPoint で閉じてもらってから上書きする。

## 道具

以下の `scripts/`・`references/` はこのスキルのフォルダ（`~/.claude/skills/deck-infographic/`）からのパス。作業フォルダから呼ぶときはフルパスで書く。

| ファイル | 役割 |
|---|---|
| `scripts/figlib.py` | 色・字・線画アイコン（37 個）・矢印の 3 種（`SOLID`・`DOTTED`・`DASHED`）・人と AI の円（`node`・`ai_node`）・役割の無い要素の円（`soft`）・人が確かめる印（`check_badge`）・凡例（`legend`）・円弧（`pt`・`arc`）・本文だけの書き出し（`write`） |
| `scripts/render.sh` | 図のスクリプト → HTML・SVG・JSON → 2 倍の PNG。PNG の大きさが JSON の 2 倍かを確かめる |
| `scripts/build_deck.py` | 元の pptx ＋ PNG ＋ JSON → 案のページを足した新しい版。元のパーツが変わっていないことを確かめ、`build-report.json`（ページごとに外した図形・残した図形）を書く。`--dry-run` で図形ごとの位置と分け方だけを出す |
| `references/example-cycle.py` | 循環＋中心＋土台＋結果の列の例。新しい図はこれを写して始める |
| `references/figure-types.md` | 内容の関係から図の型を選ぶ表 |

## 手順

### 1. ページの棚卸しと候補一覧（描く前に 1 回確認）

1. `python <pptx skill>/scripts/slide_text.py <最新版>.pptx` で全ページの文言を出し、画像にして全体を見る。
2. ページごとに図にする価値を判定し、候補一覧 md を作る。列は「元のページ｜タイトル｜図の型｜図で伝える関係（1 行）｜図に入れる実文言」。
   - **対象**：全体像、役割分担（人と AI、組織と現場）、情報の流れ、工程、比較、循環、前提と結果の関係を文章で説明しているページ。
   - **対象外**：表紙・目次・章扉、スクリーンショットや実画面が主役のページ、すでに図が主役のページ、手順の細部・注意事項・TODO が主役のページ、文がごく短いページ、案件どうしの優劣に読める比較になるページ。対象外にした理由も一覧に 1 語で残す。
   - 同じ関係を描く候補が複数ページにあるときは 1 つに畳み、どこに置くかを書く（原則 3）。
3. 候補一覧を依頼者に見せ、対象ページと図の型を 1 回だけ確かめてから描く。依頼者が「全部任せる」と言っていれば確認は省き、一覧は記録として残す。

### 2. テンプレートの座標を確かめる（最初に 1 回）

`build_deck.py` は、元のページの図形を上端の高さで「タイトル」「リード」「本文」「フッター」に分ける（位置を持たないプレースホルダーは、レイアウト・マスターの位置を使う）。既定値（1920×1080 換算の px）は次のとおり。最初に `python3 <スキル>/scripts/build_deck.py <最新版>.pptx --dry-run --pages <対象ページ>` で図形ごとの位置と分け方を出し、合わなければ引数で合わせる。

| もの | 既定 | 引数 |
|---|---|---|
| 外す本文の図形（上端） | 240〜990 | `--body-top`・`--body-bottom` |
| タイトルの枠（上端） | 60〜90 | `--title-y` |
| リードの枠（上端） | 200〜230 | `--lead-y` |
| ページ番号の枠 | 図形名 `SlideNumber`、x=1450・幅 350 に広げる | `--footer-name`・`--footer-x`・`--footer-w` |

図の本文の範囲（`figlib.write` の既定）は x=96〜1824・下端 985。**上端はページごとに異なる**（リードが 1 行か 2 行か、罫線の位置）ので、図ごとに元のページのリードの下端を見て `TOP` を決める。

### 3. 図を 1 枚ずつ描く

1. `<スキル>/scripts/figlib.py` を `source/<版>/` に写し、`<スキル>/references/example-cycle.py` を `source/<版>/figNN_<内容>.py` に写して書き換える。`PAGE`（元のページ番号）と `TOP`（本文の上端）を先に決める。
2. 図の型を内容から選ぶ（`references/figure-types.md`）。元の配置をなぞらず、関係が一目で分かる配置・視線の流れ（左上 → 右下、中心 → 周り）にする。
3. 文言は元ページか依頼文の実文言をそのまま使い、図の側で新しい主張・工程・実績・数値を足さない。足してよいのは「図の見方」「この循環を支えるもの」「本流」のような読み方のラベルだけで、足したものは記録の表に書く。図に収めるために語順を入れ替えた・2 項目を「・」でつないだ所も記録に書く。
4. タイトル・リードは原則として元のページのまま。図に合わせて変えるときだけ `write(..., title=..., lead=...)` に渡す（pptx の文字が差し替わる）。
5. `<スキル>/scripts/render.sh source/<版>/figNN_<内容>.py inputs/<版>/NN-<内容>.png` で書き出す（出力のフォルダが無ければ作る）。
6. 確かめる（毎回）：
   - PNG が JSON の幅・高さの 2 倍であること（render.sh が確かめる）。
   - 図に入れるべき文言を SVG に grep し、全部あること（`&`・`<`・`>` は SVG の中では `&amp;`・`&lt;`・`&gt;` になる）。
   - Read の表示は縮小されるので、文字が密な所を 3〜4 か所、原寸で切り出して見る（文字と矢印の重なり、切れた字、凡例が範囲からはみ出していないか）。
7. 最初の 1 枚は、すぐ依頼者に見せて方向性を確かめてから残りを描く。

### 4. 新しい版の pptx

1. `python3 <スキル>/scripts/build_deck.py <最新版のコピー>.pptx <新版>.pptx --figures inputs/<版> --meta source/<版> --tag <版>` で組む。
   - 案のページは元のページの複製で、本文の図形を外して図の PNG を貼り、ページ番号の枠を「元p.N 差し替え候補」にする。N と JSON の `page` は、元の pptx でのページの並び順（1 始まり）。表示のページ番号が並び順と異なる資料や、案を足し済みの資料にもう一度かけるときは、その pptx での並び順で数える。
   - 複製にはコメント・ノート・アニメーションを持ち込まない。セクションがあれば、案のページを元のページと同じセクションに入れる。
   - 元のページのパーツがバイト単位で変わっていないこと（変えるのは `presentation.xml`・その rels・`[Content_Types].xml`・`app.xml` だけ）をスクリプトが確かめる。次のときは止まる：出力が元の pptx と同じファイル、本文の範囲に図形が無い、位置の分からない図形がある、差し替えを指定したタイトル・リードの枠が見つからない、フッターの枠が無い、グラフ・SmartArt などが本文の外に残っていて元のページと共有になる、`--tag` が既存のパーツと重なる。
2. `python <pptx skill>/scripts/office/validate.py <新版>.pptx --original <最新版>.pptx` を通す。
3. LibreOffice で全ページを画像にし、案のページでタイトル・リード・フッターと図の位置が合っているかを見る。soffice は `-env:UserInstallation=file://<一時フォルダ>` で別のプロファイルを使う（使用中のプロファイルがあると、何も出さずに失敗する）。

### 5. 記録と仕上げ

- 制作記録に、出力のパス、作り方、足した読み方のラベル（表）、対象外にしたページと理由、未確定の事項の扱い、確かめたこと・確かめていないこと（PowerPoint での実表示、依頼者の採否）を書く。元資料と記録の食い違い（ページ数など）も残す。
- 全部描き終えたら、仕上げに 1 回だけ、作成とは別の目でレビューする（グローバルの CLAUDE.md の手順）。材料は候補一覧 md・元のページの全文言・案のページの画像と SVG・依頼と決まったこと。見る観点は「レビューで見ること」。
- 依頼者に返すときは、案のページの新版での位置（通し番号）と、案を採ったときに資料から消える元のページの注意書きを添える。

## デザインの既定（依頼に指定があればそちらに従う）

- 座標は pptx のページと同じ 1920×1080 で描き、本文の範囲だけを 2 倍で書き出す。白地。
- 色は濃い青（`#0035B4`）・薄い青（`#EEF3FC`、線は `#D3DDF3`）・濃いグレー（文字 `#2F3437`、補足 `#5F666D`、別の意味の線 `#6B737B`）。
- 図の中のラベルと説明はヒラギノ角ゴ（W3 と W6）。明朝はタイトル（pptx の文字）に任せ、図には使わない。見出しラベル 25〜30px、説明 19〜24px、凡例 17px を目安にする。
- 線画のアイコン（線の太さ 2px 前後、角丸）と、意味のある図形・矢印を使う。写真・立体・派手な装飾・ロボットのキャラクターは使わない。
- 文字を四角い箱に入れて並べるだけの構成にしない。箱を使うのは土台・帯・区分（「自分のPC」「クラウド」のような枠）など図の中で役割があるときだけ。
- 余白を取り、文字と矢印を重ねない。矢印がラベルを横切るときは、外側を回すか、円の別の縁から出す。説明文は短くし、図を主役にする。
- ロゴ・ページ番号・Confidential・制作上の注記は図に入れない（pptx の文字のフッターに任せる）。
- 図の中も和文と英数字の間に半角スペースを入れない（原則 73）。

## 内容の決まり

- **矢印の意味を分ける**：作業の順序（実線）、情報の参照・更新（点線）、改善の戻し先（灰色の破線）。凡例「図の見方」は、線を 2 種類以上使うとき、1 種類でも線だけでは意味が読めないとき、共通の意味から外して使うとき（組織から現場へ「型と支援を渡す」実線など）に置く。凡例の言葉は図での使い方に合わせる（記録と参照の両方に点線を使うなら「記録と参照」）。線以外の意味のある印（フォルダの印・太字の優先など）も凡例に入れる（`legend(..., extra=...)`）。
- 戻しの破線にはそれぞれラベルを付け、方向ごとに中身が異なれば分ける。複数の要素から戻すときは、要素を束ねた所から 1 本出す（1 つの要素からだけ出すと、対象が狭く見える）。
- **目的・ゴールは上に置く**。下の帯に置くと土台（支えるもの）に見える。
- **人と AI を見分けられるようにする**：位置（左右・上下）と塗り（人は塗り、AI は白抜き）で分け、凡例に書く。**塗りの円と白抜きの円は人と AI のためだけに使う**。人でも AI でもないもの（案件の情報・場面・案件・取り組み・コミット）は薄い青の円（`soft`）にし、優先度などは太字・青の縦線で示す。
- **AI が最終判断する図にしない**。採否・確定は人の側に置き、AI の下書きから人の判断への線を描く。AI による記録・更新・まとめには、人が確かめる印（`check_badge`）を付ける。
- 根拠のない実績・数値・新しい工程を足さない。品質の向上を「ミスが無くなる」と書かない。
- 未確定の事項（TODO・確認待ち・提供前の機能・試作中）は、元のページの書き方より強く断定しない（原則 35・53）。元のページの限定・注記（「〜はまだ試していない」「〜による話で、記録で確かめるのはこれから」）は図にも残す。
- リードが約束していること（「場面ごとの困りごと」など）は図に描く。
- 個人名・案件名・進み具合の記号（☑・☐）・取り組みごとの到達点は図に入れず、チーム・役割の単位で描く。細部は元のページに任せる。
- 注記の句読点は元のページに合わせる。
- 区分の枠に入れるものは、実際にそこにあるものだけにする（クラウドのサービスを「自分のPC」の枠に入れない）。

## レビューで見ること

過去のレビューで両方のレビュアーが挙げた点を先に見る。

- 人と AI の塗り分けの記号を、別の意味（場面・優先度など）に使っていないか。
- AI の記録・更新に、人が確かめる印が付いているか。AI が最終判断して見えないか。
- 凡例の言葉が、図での線の使い方と合っているか。線以外の印にも凡例があるか。
- 配置が意味を取り違えさせていないか（目的が下にあって土台に見える、戻しが 1 つの要素からだけ出ている）。
- 元のページとの食い違い、新しい主張・工程の混入、元のページの限定・注記の脱落。
- リードが約束する要素が図にあるか。区分の枠に入っているものが正しいか。

## 落とし穴

- SVG の文字は折り返さない。改行は手で入れ（`lines`）、1 行の幅は `tw()`（文字数 × 文字サイズ、英数字は 0.6）で見積もってから置く。
- アイコンを `scale()` で拡大するときは `stroke-width` を倍率で割る（`icon` がやる。`vector-effect` は `<g>` から継がない）。
- `marker` の矢じりは線の色ごとに定義する（`figlib.DEFS` に青 2 種・灰色 1 種）。
- Chrome は `--headless=new --force-device-scale-factor=2 --window-size=<本文の幅>,<高さ> --screenshot` で書き出す。Mac 以外では環境変数 `CHROME` に Chrome（Chromium）の場所を渡す。フォントは OS のものが当たるので、Mac 以外で書き出すときはフォントを確かめる。
- 元のページのコメントの参照（`extLst` の `commentRel`）を複製に残すと、validate が「存在しない rId」で落ちる。`build_deck.py` は外す。複製にはコメントとノートを持ち込まない。
- 元のページのページ番号が自動の通し番号（`a:fld type="slidenum"`）だと、新版では元のページの番号がずれて見える。案と元のページのどちらかを外せば元の番号に戻ることを依頼者に伝える。
- 同じ pptx にもう一度案を足すときは、`--tag` を変える（パーツ名・rId が重なると止まる）。
- 図は画像なので PowerPoint では直せない。文言を直すときはスクリプトを直し、`render.sh` と `build_deck.py` をやり直す。
- 全面の画像を 1 枚ずつ並べた確認用の pptx は、方向性を早く見せたいときだけ作る。本番は本文だけの画像にする。
