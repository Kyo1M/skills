# クライアント向けの型

分析を依頼した事業側の担当者と、その先の意思決定者（役員など）に渡すレポート。読み手は数式や統計の用語より、「何が分かり、何を判断できるか」を先に知りたい。

## 構成

1. **概要**: 最初に判断の前提（データの期間・範囲・欠け・そろえていない条件）を置き、続けて何が分かったかを書く。仮説検証まで終えて判断が言える段だけ「結論」と呼ぶ
2. **背景と問い**: なぜこの分析をしたか、どの問いに答えたか。読み手（経営層など）がすでに持っている見立てがあれば、それにどう答えるかも書く
3. **問いごとに分かったこと**: 章に番号を振る。1 つのまとまりは「何を見たか → 図 → 図の読み方 → 結果 → 言えること」
4. **解釈とまだ言えないこと**: 問い同士の関係、競合する説明（別の理由で同じ結果が出ていないか）、まだ言えないこと
5. **次にやること**: 次に確かめること、判断に要る追加のデータ、相手に確かめること（図か抜粋の表を添える）
6. **再現情報**（末尾に短く）

## 書き方

- 本文に数式を出さない。指標は業務の言葉で定義する（例: 「定着率」ではなく「入社から 1 年後に在籍している人の割合」を初出で書く）
- 統計の用語は言い換える（「有意」→「偶然とは言いにくい差」など）。言い換えられないときは初出で 1 文の説明を添える。分布・欠損・内訳のような分析の標準の用語は、読み手が分析者・データの持ち主の側なら言い換えない（`analysis-plan/references/analysis-principles.md` の 11）
- 判断を誤らせる前提（データの期間・範囲・欠け・対象外の店舗など）は、限界の節に回さず結論の近くに書く
- 数値は判断に使う粒度で出す（桁をそろえ、比べるものを並べる）
- 図は 1 図 1 指標にし、図の読み方を 1〜2 文で添える。メッセージの数だけ図を置き、図から直感的に読めるメッセージにする
- 経営層向けの示唆は、業績（売上そのもの・予算比・前年比）とのつながりで書く。つながりが確かめられていない段では「仮説」「次に確かめる」と明記する
- 既存のスコア・KPI を相手が使い続ける前提なら、分析の結果からロジックへの示唆（重み・頭打ち・欠けの扱いなど）を出す
- 文章はグローバルの書き方原則（`~/Developer/Skills/deck-outline/references/writing-principles.md`）に従う。特に、相手の語彙で書く、検証できる行動で書く、AI っぽさを消す、導入は「無いことで何ができなかったか」まで書く
