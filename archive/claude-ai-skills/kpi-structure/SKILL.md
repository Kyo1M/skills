# KPI構造分解スキル

クライアントの事業KGIをロジックツリー型で分解し、実用的なKPI構造を設計する。

## ワークフロー

```
1. 事業概要のヒアリング
2. KGIの確認・言語化
3. KPIへのロジックツリー分解
4. 各KPIの詳細化
5. 構造の出力（テーブル＋ツリー）
```

**注意**: 各ステップを完了してから次に進む。ユーザーに確認しながら進める。

## Step 1: 事業概要のヒアリング

### 目的
KPI設計に必要な事業コンテキストを把握する。

### 聞き出す情報

**基本情報**
- クライアント名（任意）
- 事業・サービスの概要
- ビジネスモデル（BtoB/BtoC、サブスク/売り切り等）
- 主要な収益源

**現状把握**
- 現在追っている指標（あれば）
- データ取得環境（BIツール、DB等）
- 課題感（なぜKPI整理が必要か）

### 質問の進め方

1. まず事業概要を1〜2問で確認
2. 回答に応じて深堀り
3. 一度に多くを聞きすぎない（3問程度まで）

### 出力

```
## 事業概要サマリー

- **事業/サービス**: ___
- **ビジネスモデル**: ___
- **収益源**: ___
- **現状の指標**: ___
- **課題感**: ___
```

## Step 2: KGIの確認・言語化

### 目的
分解の起点となるKGI（最終目標指標）を明確にする。

### 確認事項

**KGIの特定**
- 事業として最も重要な目標指標は何か
- 複数ある場合は優先順位を確認
- 時間軸（月次/四半期/年次）

**KGIの定義**
- 計算式・算出方法
- 現在値と目標値（把握していれば）

### 代表的なKGI例

| ビジネスモデル | 代表的なKGI |
|--------------|------------|
| サブスク | MRR, ARR, LTV |
| EC | 売上高, GMV |
| メディア | MAU, DAU, ARPU |
| SaaS | NRR, Churn Rate |
| アプリ | DAU, 継続率, ARPU |

### 出力

```
## KGI定義

| 項目 | 内容 |
|------|------|
| KGI | ___ |
| 定義/計算式 | ___ |
| 時間軸 | 月次 / 四半期 / 年次 |
| 現在値 | ___（任意） |
| 目標値 | ___（任意） |
```

## Step 3: KPIへのロジックツリー分解

### 目的
KGIを構成要素に因数分解し、階層的なKPI構造を作成する。

### 分解の原則

**1. 四則演算で分解**
```
売上 = 客数 × 客単価
客数 = 新規客数 + 既存客数
客単価 = 購入回数 × 1回あたり単価
```

**2. MECEを意識**
- 漏れなくダブりなく分解
- 同じ階層は同じ粒度で

**3. 3〜4階層を目安**
- 深すぎると実用性が下がる
- 浅すぎると施策に落ちない

### 代表的な分解パターン

参照: `references/decomposition-patterns.md`

**売上系**
```
売上 = 顧客数 × ARPU
     = 顧客数 × (購入頻度 × 購入単価)
```

**LTV系**
```
LTV = ARPU × 平均継続期間
    = ARPU × (1 / Churn Rate)
```

**MAU系**
```
MAU = 新規ユーザー + 復帰ユーザー + 継続ユーザー
継続ユーザー = 前月MAU × 継続率
```

### 進め方

1. KGIの第1階層分解を提案
2. ユーザーと確認・調整
3. 第2階層以降を順次分解
4. 各階層で妥当性を確認

### 出力（ツリー構造）

```
## KPIツリー構造

[KGI] 売上高
├── [KPI] 顧客数
│   ├── [KPIドライバー] 新規獲得数
│   │   ├── リード数
│   │   └── CVR
│   └── [KPIドライバー] 既存継続数
│       ├── 前月顧客数
│       └── 継続率
└── [KPI] ARPU
    ├── [KPIドライバー] 購入頻度
    └── [KPIドライバー] 購入単価
```

## Step 4: 各KPIの詳細化

### 目的
各KPIを実運用可能なレベルまで定義する。

### 定義項目

| 項目 | 説明 |
|------|------|
| KPI名 | 指標の名称 |
| 定義 | 何を測るか、計算式 |
| 種別 | 先行指標 / 遅行指標 |
| 計測頻度 | 日次/週次/月次 |
| データソース | どこから取得するか |
| 担当 | 誰が責任を持つか（任意） |

### 先行指標 vs 遅行指標

| 種別 | 特徴 | 例 |
|------|------|-----|
| 先行指標 | 将来の結果を予測、施策で動かしやすい | リード数、CVR、アクティブ率 |
| 遅行指標 | 結果を示す、直接コントロールしにくい | 売上、LTV、Churn Rate |

**原則**: 上位階層ほど遅行、下位階層ほど先行になる傾向

### 進め方

1. ツリーの末端（KPIドライバー）から詳細化
2. データ取得可否を確認
3. 取得できない場合は代替指標を検討

## Step 5: 最終出力

### 出力形式

**1. KPIツリー構造（俯瞰用）**

```
[KGI] ___
├── [KPI] ___
│   ├── [ドライバー] ___
│   └── [ドライバー] ___
└── [KPI] ___
    ├── [ドライバー] ___
    └── [ドライバー] ___
```

**2. KPI詳細テーブル**

```markdown
## KPI詳細一覧

| # | 階層 | KPI名 | 定義/計算式 | 種別 | 計測頻度 | データソース | 備考 |
|---|------|-------|------------|------|---------|-------------|------|
| 1 | KGI | ___ | ___ | 遅行 | 月次 | ___ | ___ |
| 2 | KPI | ___ | ___ | 遅行 | 月次 | ___ | ___ |
| 3 | ドライバー | ___ | ___ | 先行 | 週次 | ___ | ___ |
```

**3. KPI説明（各指標の詳細）**

```markdown
### [KPI名]

- **定義**: ___
- **計算式**: ___
- **種別**: 先行 / 遅行
- **なぜ重要か**: ___
- **改善施策例**: ___
```

### 最終出力フォーマット

```markdown
# KPI構造設計書: [クライアント名/プロジェクト名]

作成日: YYYY/MM/DD
対象事業: ___

## 1. 事業概要
[Step 1の出力]

## 2. KGI定義
[Step 2の出力]

## 3. KPIツリー構造
[Step 3の出力]

## 4. KPI詳細一覧
[テーブル形式]

## 5. 各KPIの説明
[各指標の詳細説明]

## 6. 補足・注意事項
- データ取得に関する課題
- 今後の検討事項
```

## 注意事項

- クライアントの事業理解を優先。分解を急がない
- 「正解」を押し付けず、クライアントと一緒に設計する姿勢
- データが取れない指標は無理に入れない（代替案を提案）
- 完璧を目指さず、まず動かせる構造を作る
- 定期的な見直しを前提とした設計を推奨
